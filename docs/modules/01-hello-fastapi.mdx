## Concept

FastAPI is a **Python web framework** for building APIs. Three things matter on day one:

<CardGroup cols={3}>
  <Card title="The app object" icon="server">
    A single `FastAPI()` instance is your application. Routes attach to it.
  </Card>
  <Card title="Route handlers" icon="code">
    Python functions decorated with `@app.get(...)` etc. handle HTTP requests.
  </Card>
  <Card title="Auto-generated docs" icon="book">
    FastAPI reads your function signatures and generates Swagger UI for free at `/docs`.
  </Card>
</CardGroup>

### Why FastAPI (vs Flask, Django, etc.)

- **Type-driven** - your function's type hints become the API contract
- **Async-native** - `async def` is first-class, not bolted on
- **OpenAPI built in** - Swagger UI and ReDoc come free
- **Pydantic for validation** - request bodies validate themselves (Module 02)

### What's an "ASGI" app?

You'll see this term. WSGI is the old Python web standard (synchronous, one request at a time per worker). **ASGI** is the modern async-friendly version. FastAPI is an ASGI app, and `uvicorn` is the ASGI server that runs it.

```
HTTP request -> Uvicorn (ASGI server) -> FastAPI app -> your function -> response
```

## Walkthrough

We're starting with the simplest possible app: one endpoint, no database, no schemas. Just enough to see the request/response loop work.

Open `app/main.py`:

```python app/main.py
"""Subject Enrollment Service - entry point."""
from fastapi import FastAPI

app = FastAPI(
    title="Subject Enrollment Service",
    description="Clinical trial enrollment training app",
    version="0.1.0",
)


@app.get("/")
def root():
    """Service banner - also acts as a basic liveness check."""
    return {
        "service": "Subject Enrollment Service",
        "version": "0.1.0",
        "status": "ok",
    }
```

### Line by line

<AccordionGroup>
  <Accordion title="`from fastapi import FastAPI`">
    Imports the framework's main class. Everything starts from `FastAPI`.
  </Accordion>
  <Accordion title="`app = FastAPI(title=..., description=..., version=...)`">
    Creates *the* app object. `title`/`description`/`version` show up in the auto-generated `/docs`. They're also part of the OpenAPI spec other tools (Postman, code generators) use.
  </Accordion>
  <Accordion title="The @app.get(...) decorator">
    A **decorator** that registers the next function as the handler for `GET /`. Other verbs: `@app.post`, `@app.put`, `@app.delete`, `@app.patch`.
  </Accordion>
  <Accordion title="`def root():`">
    The handler function. The name does not matter for routing; the decorator does the routing. Convention: name it after what it does.
  </Accordion>
  <Accordion title="`return { ... }`">
    Return a dict. FastAPI converts it to JSON automatically and sets `Content-Type: application/json`. Later we return Pydantic models for proper schemas.
  </Accordion>
</AccordionGroup>

## Quick check

<AccordionGroup>
  <Accordion title="If I rename the function from `root` to `home`, will the URL change?">
    **No.** The URL is determined by the decorator argument (`@app.get("/")`), not the function name. You could call it `pneumonoultramicroscopicsilicovolcanoconiosis` and the route would still be `/`.
  </Accordion>
  <Accordion title="What happens if I write `@app.post('/')` instead of `@app.get('/')`?">
    `GET /` would return a 405 *Method Not Allowed*. `POST /` would work but you cannot easily test it from a browser address bar; you would need `curl -X POST` or Swagger UI.
  </Accordion>
  <Accordion title="Why do I need `--reload` when running uvicorn?">
    Without it, Uvicorn loads `main.py` once and ignores edits. With `--reload`, the server watches files and restarts on save. Use it in development; **never** in production.
  </Accordion>
  <Accordion title="Where does `/docs` come from? I didn't write it.">
    FastAPI ships with two built-in routes: `/docs` (Swagger UI) and `/redoc` (ReDoc). Both render the OpenAPI schema FastAPI generates from your code at `/openapi.json`. You can disable them in production by passing `docs_url=None, redoc_url=None` to `FastAPI()`.
  </Accordion>
</AccordionGroup>

## Exercise

<Tabs>
  <Tab title="Task">
    Add a second endpoint to `app/main.py`:

    ```
    GET /sites/{site_id}
    ```

    It should accept a `site_id` from the URL path and return a dict like:

    ```json
    {
      "site_id": "SITE-001",
      "name": "Example Hospital",
      "active": true
    }
    ```

    Use a hard-coded `name` for now. We'll wire up real data in later modules.

    **Constraints:**
    - Must use a path parameter (`{site_id}` in the route)
    - The handler function should be type-annotated (`site_id: str`)
    - The dict you return must echo the `site_id` you received

    You'll write **about 6 lines of code**.
  </Tab>
  <Tab title="Hint 1">
    A path parameter is declared by putting `{name}` in the route string and a matching argument in the function:

    ```python
    @app.get("/items/{item_id}")
    def get_item(item_id: str):
        return {"item_id": item_id}
    ```

    Adapt this pattern to `/sites/{site_id}`.
  </Tab>
  <Tab title="Hint 2">
    Your function signature should be:

    ```python
    def get_site(site_id: str):
        ...
    ```

    Inside, return a dict with three keys: `site_id`, `name`, `active`. The first echoes the parameter; the other two are hard-coded.
  </Tab>

## Insight

</Tip>

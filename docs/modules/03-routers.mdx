## Concept

`main.py` is starting to bloat. As we add screenings, sites, auth, jobs, we'd hit 1000 lines fast.

**`APIRouter` is FastAPI's solution.** Each resource gets its own file with its own routes; `main.py` just *includes* them with a prefix.

```
app/
├── main.py              ← creates app, includes routers
└── routers/
    ├── screenings.py    ← all /screenings endpoints
    └── sites.py         ← all /sites endpoints
```

This is **the** structure used by every production FastAPI codebase.

### Three kinds of parameters

| Kind | Example | Where it lives |
|---|---|---|
| **Path** | `/screenings/{id}` | URL itself, always required |
| **Query** | `?status=eligible&limit=50` | URL query string, usually optional |
| **Body** | JSON object on POST/PUT | Request body, declared with a Pydantic schema |

FastAPI infers which is which from your function signature: types in the URL = path, types in the function = query (unless they're a Pydantic model = body).

```python app/routers/sites.py
"""Site routes."""
from fastapi import APIRouter, HTTPException

from app.schemas.site import SiteResponse

router = APIRouter(prefix="/sites", tags=["sites"])

_SITES: list[SiteResponse] = [
    SiteResponse(id="SITE-001", name="Mass General", active=True),
    SiteResponse(id="SITE-002", name="Stanford Health", active=True),
    SiteResponse(id="SITE-003", name="Old Site", active=False),
]


@router.get("", response_model=list[SiteResponse])
def list_sites(active: bool | None = None):
    """List sites. Filter by active status with `?active=true`."""
    if active is None:
        return _SITES
    return [s for s in _SITES if s.active == active]


@router.get("/{site_id}", response_model=SiteResponse)
def get_site(site_id: str):
    for site in _SITES:
        if site.id == site_id:
            return site
    raise HTTPException(status_code=404, detail=f"Site {site_id} not found")
```

```python app/routers/screenings.py
"""Screening routes."""
from datetime import datetime
from uuid import UUID, uuid4

from fastapi import APIRouter, HTTPException

from app.schemas.screening import ScreeningCreate, ScreeningResponse

router = APIRouter(prefix="/screenings", tags=["screenings"])

_screenings: dict[UUID, dict] = {}


@router.post("", response_model=ScreeningResponse, status_code=201)
def create_screening(payload: ScreeningCreate):
    screening = {
        "id": uuid4(),
        "status": "submitted",
        "created_at": datetime.utcnow(),
        **payload.model_dump(),
    }
    _screenings[screening["id"]] = screening
    return screening


@router.get("", response_model=list[ScreeningResponse])
def list_screenings(
    site_id: str | None = None,
    status: str | None = None,
    limit: int = 50,
):
    """List screenings, optionally filtered by site or status."""
    items = list(_screenings.values())
    if site_id:
        items = [s for s in items if s["site_id"] == site_id]
    if status:
        items = [s for s in items if s["status"] == status]
    return items[:limit]


@router.get("/{screening_id}", response_model=ScreeningResponse)
def get_screening(screening_id: UUID):
    if screening_id not in _screenings:
        raise HTTPException(status_code=404, detail="Screening not found")
    return _screenings[screening_id]
```

### Step 2 — Slim down `main.py`

```python app/main.py
"""Subject Enrollment Service — entry point."""
from fastapi import FastAPI

from app.routers import screenings, sites

app = FastAPI(title="Subject Enrollment Service", version="0.3.0")

app.include_router(sites.router)
app.include_router(screenings.router)


@app.get("/")
def root():
    return {"service": "Subject Enrollment Service", "status": "ok"}
```

That's it. `main.py` is back to being scannable.

### What's new

<AccordionGroup>
  <Accordion title="`APIRouter(prefix='/sites', tags=['sites'])`">
    `prefix` is prepended to every route in this router (so `@router.get("")` becomes `GET /sites`). `tags` groups endpoints together in `/docs` — refresh and you'll see "sites" and "screenings" sections.
  </Accordion>
  <Accordion title="`active: bool | None = None`">
    A **query parameter**. Because it has a default value and a primitive type, FastAPI knows it's a query param. URL: `/sites?active=true`. The type coercion is automatic — `?active=true` becomes Python `True`.
  </Accordion>
  <Accordion title="`screening_id: UUID`">
    A **path parameter** (because `{screening_id}` is in the route string) typed as `UUID`. FastAPI parses the URL fragment as a UUID; if it's not valid UUID syntax, you get a 422 automatically.
  </Accordion>
  <Accordion title="`payload: ScreeningCreate`">
    A **body parameter** (because the type is a Pydantic model). FastAPI knows this from the type alone.
  </Accordion>
  <Accordion title="`app.include_router(screenings.router)`">
    Mounts the router into the app. You can also override the prefix here: `app.include_router(screenings.router, prefix="/api/v1")`. We'll do that in Module 04 for API versioning.
  </Accordion>
</AccordionGroup>

## Quick check

<AccordionGroup>
  <Accordion title="What's the difference between `prefix` on the router vs on `include_router`?">
    Both work. Prefer the **router** for "this resource lives at this URL" (`/sites`); use **include_router** for cross-cutting prefixes ("everything is under `/api/v1`"). Module 04 does both.
  </Accordion>
  <Accordion title="When should I use `tags`?">
    Always. They organize `/docs`. Convention: one tag per resource, lowercase plural (`["sites"]`, `["screenings"]`).
  </Accordion>
  <Accordion title="Can I have multiple routers handle the same path?">
    Technically yes, but don't. The first registered wins. Keep one router per resource.
  </Accordion>
  <Accordion title="What about `@router.delete` and `@router.put`?">
    Same syntax as `get`/`post`. Conventions: `DELETE /screenings/{id}` for delete, `PUT /screenings/{id}` for full replace, `PATCH /screenings/{id}` for partial update.
  </Accordion>
</AccordionGroup>

<Tabs>
  <Tab title="Task">
    Add a `DELETE /screenings/{screening_id}` endpoint.

    Behavior:
    - If the screening exists and `status == "submitted"`, remove it from `_screenings` and return 204 (no content).
    - If it exists but status is anything else, return **409 Conflict** with detail `"Cannot delete screening in status X"`.
    - If it doesn't exist, return 404.

    The DELETE route should NOT have a response model (use `status_code=204` and return `None`).
  </Tab>
  <Tab title="Hint">
    Use `status_code=204`. For 204, return `None` from the function (FastAPI sends an empty body). For 409, raise `HTTPException(409, "...")`.

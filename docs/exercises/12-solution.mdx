## The problems

```python
async def fetch_external_then_save(db, payload):
    time.sleep(0.5)                                    # ← Bug #1
    response = requests.post(".../audit", json=payload) # ← Bug #2
    response.raise_for_status()
    return await repo.create(db, **payload)
```

**Bug #1 — `time.sleep`:** Blocks the event loop for 500 ms. Under 50 concurrent requests this is 25 seconds of loop freeze.

**Bug #2 — `requests.post`:** Same issue. The library is fully synchronous; the HTTP call itself blocks. Network latency to `api.example.com` could be hundreds of ms.

## The fix

```python
import asyncio
import httpx

async def fetch_external_then_save(db, payload):
    await asyncio.sleep(0.5)                                # async sleep
    async with httpx.AsyncClient() as client:               # async HTTP
        response = await client.post("https://api.example.com/audit", json=payload)
    response.raise_for_status()
    return await repo.create(db, **payload)
```

## Bonus problem

Even with the fix, opening a fresh `AsyncClient()` per call is wasteful. In real code you'd:

1. Create one `httpx.AsyncClient` in `lifespan` and store it in `app.state`.
2. Inject it via a dep (`get_http_client`).
3. Reuse the connection pool across requests.

```python
# main.py lifespan
app.state.http = httpx.AsyncClient(timeout=10.0)

# dependencies.py
def get_http_client(request: Request) -> httpx.AsyncClient:
    return request.app.state.http
```

## Notes

<AccordionGroup>
  <Accordion title="Why is this a hidden bug?">
    Both `time.sleep` and `requests` work in `def` (sync) handlers. They only become bugs when you *also* declare `async`. The function still appears to work in development with low load — the symptoms only show up under concurrent traffic.
  </Accordion>
  <Accordion title="What about `raise_for_status()` — is that async-safe?">
    Yes. `httpx`'s response object has a sync `raise_for_status()` because it doesn't do I/O — it just inspects status code. Don't wrap it in `await`.
  </Accordion>
</AccordionGroup>
